## 追加：从「单文件」升级为「可安装 PWA」并发布

### 起因
用户反馈手机 Chrome 菜单里**没有「安装应用 / 添加到主屏幕」**。截图显示地址栏是 **`content://...`**（文件管理器把本地文件交给 Chrome 打开的形态）。

### 关键结论（查证所得）
- 安卓 Chrome **只对 http(s) 页面**显示「添加到主屏幕 / 安装应用」；`file://` 与 `content://` 一律不提供。这是 URL scheme 决定的，跟 manifest 写得对不对无关。
- `content://` 是不透明源，**localStorage 可能被禁用** → 数据静默丢失。已在应用里加 `probeStorage()` 探测 + 顶部常驻红色警告条。
- Chrome 可安装性标准（现版本）：**从菜单安装**不再要求 Service Worker（移动版 108 / 桌面版 112 起取消）；但 **`beforeinstallprompt` 仍要求存在带 `fetch` 处理器的 Service Worker**。所以没有 SW 时不会自动弹安装提示，但菜单里的「安装应用」仍然可用。
- manifest 的 `start_url` 规范要求与文档同源；manifest href 允许跨源（需 CORS）。`blob:` manifest 规范未禁止但兼容性不确定 → 托管版改用**真实 manifest 文件**。

### 本次改动
1. `学习工作台.html`（单文件版，仍保留）新增：
   - `probeStorage()` + `showStorageWarning()` 顶部常驻警告条（存储不可用时不再反复弹 toast）
   - `registerSW()`：仅在 `https:` 或 `localhost` 下注册 `./sw.js`，本地打开自动跳过
   - `injectManifest()` 加守卫：页面已有静态 manifest 时不再注入 blob 版，避免两个 manifest 打架
   - 存储信息弹层新增「存储是否可用 / 当前页面地址」两行
   - 「添加到主屏幕」说明改写准确：明说 Chrome 只对 http(s) 提供该选项
2. 新增 `构建发布目录.js`：以单文件版为唯一源，生成 `发布/`（index.html + manifest.webmanifest + sw.js + 3 个 PNG 图标）。含**手写极简 PNG 编码器**（node 内置 zlib + 自实现 CRC32），画蓝紫渐变秒表图标，4x4 超采样抗锯齿。

### 发布结果
- 分享链接：`https://09db56bcee8944149e243bac5c1fc74b.sg.agentos-app.run`
- 实测 `beforeinstallprompt` **已触发**（页面显示「一键安装到主屏幕」按钮）→ Chrome 认定可安装，Service Worker `active`，三个图标全 200。
